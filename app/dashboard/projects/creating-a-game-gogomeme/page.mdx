## Short Story Description:

Me and my friend wanted to particapte in a game jam as a way to have a defined goal and deadline for a project to participate in, we stumbled on the [Brainless Game Jam](https://itch.io/jam/brainless-mini-game-jam) and due to its week only long focus it gave us ample oppertunity to practice skills while not overcommiting to a project.

### Unity
I selected the platform [Unity](https://en.wikipedia.org/wiki/Unity_(game_engine)) to create the game on, as I had prior experience with the platform and have build out different games before hand. The ideal situation was to use the 2D camera system along with re-applying code to help build the initial foundations such as movement and control.

Using the unity system was seamless as I had learnt how the tool functions and due to the long term existence of the platform there were various tutorials in place which I had watched and applied when making the game. 

Tools which I found useful were the new Input System and the various component system. The input system was useful as it allowed you to have a control scheme that could be easily converted and used by controller system or other input controllers. This is helpful in supporting individuals who may only be able to play with certain controls or systems in place. Along with that the component system is great as it helps to create systems and structures for your models or mechanics without needed to manually code or develop the system your self which is great, allowing you to focus on game development.

#### Implementing Game Mechanics
This was the rough part of trying to build the overall mechanics as I had come off making a 3D game. A problem I faced was using something like a collider which I had applied in the 3D game and worked effectively but when using it for a 2D game its functionality was different and this caused issues when I would try to implement the enemy system along with the ground system. Where with 3D games items and platforms would have automatic [colliders](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Collider2D.html), within the 2D setting I would need to ground the objects and have checks in place for the player to jump. In future I should look at examples for 2D games and plan how it would work, since the unity API is not simply just a plug an play system. I just went in with the idea that it would simply work.

Another mechanic was the enemy aiming system, which just tracked the player position at all times and the bullets would spawn at set random intervals and get launched at different speeds to create variety with the game challenge. With the spawned bullets having the ability to be launched back at the enemy, with the parry mechanic.

Talking about the parry mechanic, it relied on having a micro collider to spawn in front of the player and due to the bullets having a set trigger that when they interacted with the player parry collider they would be launched back in the opposite direction simply converting the velocity into a negative number and the colour being changed. When coding it all I had to do was extend out the bullet physics script to include the detail about the bullet and prep for that specific condition while just creating the collider and setting a specific tag to ensure that it would randomly be parried when not done by the player directly.

Some extra features and functionality that I added was empty materials to allow the enemies to be moved back and forth, to create more of a challenge and reduce the static feeling when trying to play the game. Along with implementing a timer into a game to create more of a how long can you last type of feel and finally some instructions on the controls though very poorly done due to a lack of not knowing how the canvas systems worked.
